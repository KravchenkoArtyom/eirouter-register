# Универсальный регистратор

Движок берёт сценарий сайта (`universal_scenarios/*.json`) и повторяет его
шаги в браузере: заполняет форму, при необходимости ждёт письмо, отправляет и
проверяет успех. Специфика сайта живёт в сценарии, Python править не нужно.

## Запуск

Панель: `scripts\webui.bat` → раздел «Запуск» (см. [webui.md](webui.md)).

Консоль: `scripts\universal_autoregister.bat` или `py -3 -m universal`.
Вопросы по порядку: прокси → почтовый сервис → сценарий → количество.
То же без вопросов:

```powershell
py -3 -m universal --scenario universal_scenarios/my-site.json --count 3 --mail-service tmail --direct
py -3 -m universal --count 1 --mail-service mail.tm --use-proxies
```

`--browser auto|chrome|adspower`, `--output PATH`, `--proxy URL`,
`--proxies-file PATH`, `--rotation`, `--ban-after`, `--captcha-mode`,
`--captcha-timeout`, `--step-delay MIN_MS MAX_MS`,
`--account-pause MIN_S MAX_S`. Каждый запуск пишет консоль в
`logs/run_ГГГГ-ММ-ДД_ЧЧ-ММ-СС_микросекунды.log`; ключи и данные прокси в логах
маскируются.

## Почта

`none` — без ящика, `tmail` (он же `wibucrypto`) — браузерный клиент
tmail.wibucrypto.pro, `mail.tm` — по API. Оба сервиса умеют и код, и ссылку
подтверждения; почтовые шаги можно ставить в любое место сценария — см.
[mail-actions.md](mail-actions.md). Любой другой сайт временной почты
добавляется своим сервисом — [mail-services.md](mail-services.md).

## Сеть и профили

Прокси берутся из `proxies.txt` (по одному URL в строке, пример —
`proxies.example.txt`), из списка в панели или из `--proxy`; пустой список
означает системный маршрут. Аккаунты получают адреса по правилу ротации
(по кругу, случайно, липко, после ошибки), мёртвые адреса выпадают из
очереди — [proxies.md](proxies.md). Браузер и Mail.tm идут через один и тот
же прокси.

Профили запусков лежат в `universal_profiles/`. С AdsPower (файл
`adspower.local.json` с `api_key`) на каждый аккаунт создаётся отдельный
профиль, который удаляется после успешного сохранения; без него используется
персистентный профиль Chrome. Подробности про AdsPower и отпечатки —
в [eirouter.md](eirouter.md).

## Результат

Аккаунты дописываются в `universal_accounts.json`: `email`, `password`,
`provider` (имя сценария), `status`, `device_uuid`. Пока сценарий не дошёл до
конца, статус `registration_pending`; после успеха — `active`. Файл пишется
атомарно, с правами «только владелец», и одно хранилище обслуживает весь
запуск, поэтому параллельные аккаунты не спорят за файл.

Неудачный аккаунт не останавливает очередь: следующий запускается с чистым
профилем. Ошибка шага называет секцию, номер и действие
(`steps 4/7 (click): TimeoutError: …`), а рядом остаётся снимок падения —
`logs/failures/<id запуска>/<время>_<аккаунт>/` со `screen.png`, `page.html` и
`error.json`. Сценарий проверяется до запуска браузера: с ошибками в описании
запуск не начнётся.

CAPTCHA и подобные проверки регистратор не обходит, но замечает: запуск
встаёт на паузу и зовёт человека (полоса в панели, сигнал в консоли).
Пройдите проверку в видимом окне браузера — сценарий продолжится; можно
пропустить аккаунт или остановить очередь. Задержки между шагами и
аккаунтами настраиваются там же — [delays-and-captcha.md](delays-and-captcha.md).
