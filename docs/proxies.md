# Прокси

Прокси можно задать тремя способами, и все три доступны из панели
(раздел **«Прокси»**) и из консоли.

| Способ | Где | Когда удобно |
| --- | --- | --- |
| Файл | `proxies.txt` в корне (пример — `proxies.example.txt`) | обычный случай: список живёт между запусками |
| Список в панели | текстовое поле, «Сохранить список» пишет тот же файл | пачку адресов дали текстом или файлом |
| Один адрес | «Запуск» → сеть «Один адрес вручную» | быстрая проверка одного прокси |

Формат строки: `http://user:password@host:port` или короче — `host:port`
(схема `http://` добавится сама). Пустые строки и строки с `#` — комментарии.
Один адрес в строке, повторы убираются.

Схемы: `http`, `https`, `socks5` (и `socks5h`). У socks5 логин и пароль
указать нельзя — Chromium их не принимает, поэтому нужен адрес вида
`socks5://host:port`; `socks4` не поддерживается. О каждой отклонённой строке
панель говорит отдельно, с номером строки и причиной.

Файл можно перетащить прямо на поле («Перетащите файл со списком»): браузер
читает его сам и дописывает в поле — останется нажать «Сохранить список».
Ошибочные строки перечисляются с номерами; можно сохранить только корректные.

## Проверка связи

«Проверить связь» дёргает через каждый прокси `https://api.ipify.org` и
показывает таблицу: время ответа и внешний IP или причину отказа.
Проверяются первые 40 адресов, по 5 одновременно. Логины и пароли в
результатах и в логах скрыты — виден только `схема://host:port`.

Чтобы проверить socks5, нужен дополнительный пакет:
`pip install "httpx[socks]"` (в браузере такой адрес работает и без него —
панель об этом скажет прямо в результате).

## Ротация

Правило выбирается в «Прокси» (запоминается) и в «Запуске» (на один запуск).

| Правило | Поведение |
| --- | --- |
| `per_account` | по кругу: новый аккаунт — следующий адрес |
| `random` | случайный адрес на каждый аккаунт |
| `sticky` | один и тот же адрес, пока он работает |
| `on_error` | менять только после неудачи |

«Убирать после N неудач подряд» (`ban_after`, по умолчанию 2) выкидывает
адрес из очереди. Если выпали все, запуск продолжается напрямую — об этом
будет строка в логе.

Во время запуска под прогрессом видна таблица: адрес, успехи, неудачи и
состояние («сейчас», «в очереди», «выключен»).

## Консоль

```powershell
py -3 -m universal --use-proxies --rotation per_account --ban-after 2
py -3 -m universal --proxy http://user:pass@host:8080 --proxy 10.0.0.7:3128 --rotation random
py -3 -m universal --direct
```

`--proxies-file PATH` берёт другой файл, `--proxy` можно повторять,
`--direct` отключает прокси. Браузер и Mail.tm идут через один и тот же
адрес, поэтому внешний IP страницы и почты совпадает.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/proxies` | счёт, маскированные адреса, ошибки строк, правила ротации (`?text=1` — ещё и текст файла) |
| PUT | `/api/proxies` | записать список (`text`, `ignore_errors`) |
| DELETE | `/api/proxies` | очистить список |
| POST | `/api/proxies/check` | проверить связь через каждый адрес |

Файл списка пишется атомарно и с правами «только владелец»: в строках бывают
пароли.

Код: `core/proxy_pool.py` (разбор, файл, `ProxyRotation`),
`webui/api/proxies.py` (панель), `webui/api/runs.py` (выдача адресов очереди).
