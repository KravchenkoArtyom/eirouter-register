# Как это работает — понятным языком

Регистратор — это программа, которая заполняет форму регистрации на сайте
вместо человека: открывает браузер, вписывает адрес и пароль, при
необходимости достаёт код из письма и сохраняет готовый аккаунт в файл.
Капчу она не решает: замечает проверку, ставит паузу и зовёт вас.

![Схема: панель, сценарий, браузер, сайт, почта, прокси, капча, результат](images/how-it-works.png)

Та же схема живёт в панели: раздел **«Обзор»** — первое, что видно при
открытии `scripts\webui.bat`.

## Десять частей одной картинки

| № | Часть | Что это |
| --- | --- | --- |
| 1 | **Панель в браузере** | окно на http://127.0.0.1:8765: что запускать, сколько аккаунтов, какая почта и сеть |
| 2 | **Сценарий сайта** | список шагов для одного сайта — файл `universal_scenarios/имя.json` |
| 3 | **Браузер** | обычный Chrome или профиль AdsPower; окно видно на экране |
| 4 | **Страница регистрации** | шаги выполняются по очереди с паузами, чтобы ритм не выглядел машинным |
| 5 | **Почта** | ящик для писем: встроенные tmail и Mail.tm либо свой сервис, описанный шагами |
| 6 | **Прокси** | адреса выхода в интернет: файл, список или один адрес; между аккаунтами меняются по правилу ротации |
| 7 | **Капча** | проверка «я не робот»: программа её замечает и останавливается |
| 8 | **Человек** | вы: полоса сверху панели, звук, уведомление и три кнопки — «Я решил», «Пропустить аккаунт», «Остановить запуск» |
| 9 | **Результат запуска** | строка в `universal_accounts.json`: адрес, пароль, статус; лог — в панели и в `logs/` |
| 10 | **Инспектор** | страница сайта или почты внутри панели: наведение подсвечивает элемент, клик забирает селектор в шаг |

## Путь одного аккаунта

1. Вы нажимаете «Запустить»: выбраны сценарий, число аккаунтов, почта и сеть.
2. Программа берёт прокси по правилу ротации и открывает браузер с чистым
   профилем.
3. Если сценарию нужна почта — создаётся ящик (или это делает шаг
   `mail_create` в нужный момент).
4. Открывается страница регистрации, шаги идут по очереди: `steps` →
   `verification` → `submit` → `success`. Между шагами — случайная пауза.
5. Если на экране появилась капча, запуск замирает: сверху панели полоса,
   звук, уведомление. Вы решаете проверку в окне браузера и жмёте «Я решил» —
   или «Пропустить аккаунт».
6. Понадобился код или ссылка из письма — программа ждёт письмо в ящике и
   подставляет `{code}` / `{link}` в шаг.
7. Аккаунт дописывается в `universal_accounts.json`, браузер закрывается,
   выдерживается пауза между аккаунтами — и очередь идёт дальше.

## Словарь

- **Сценарий** — список шагов для одного сайта. Один сайт — один файл.
- **Шаг** — одно действие: вписать, нажать, дождаться, взять код из письма,
  подождать человека на капче.
- **Селектор** — адрес элемента на странице (`#email`,
  `button:has-text('Register')`). Снимается инспектором в один клик.
- **Подстановка** — `{email}`, `{login}`, `{password}`, `{code}`, `{link}`:
  программа заменяет их данными текущего аккаунта.
- **Ротация** — правило, по которому аккаунты получают разные прокси.
- **Профиль** — папка браузера для одного аккаунта: cookies и настройки не
  смешиваются между аккаунтами.

## Что делает человек, а что программа

| Человек | Программа |
| --- | --- |
| один раз описывает шаги сайта (помогает инспектор) | повторяет их для каждого аккаунта |
| решает капчу и другие проверки | замечает проверку, ставит паузу, зовёт и ждёт |
| даёт список прокси | раздаёт адреса аккаунтам и убирает мёртвые |
| выбирает почтовый сервис | создаёт ящик, ждёт письмо, достаёт код или ссылку |
| смотрит лог и файл аккаунтов | пишет лог, сохраняет аккаунты, держит паузы |

## Границы

Программа не обходит капчу, SMS-подтверждение и прочие проверки доступа —
она их только замечает и передаёт человеку. Регистрируйте аккаунты там, где
это разрешено правилами сайта.
