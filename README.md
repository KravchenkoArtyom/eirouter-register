# universal-autoregister

Универсальный регистратор аккаунтов для Windows: панель в браузере, движок
сценариев (любой сайт с формой регистрации) и готовые регистраторы сервисов
на NewAPI — eirouter и wisdomsatan. Новый сайт добавляется сценарием в панели,
а не правкой кода.

![Как работает регистратор: панель, сценарий, браузер, сайт, почта, прокси, капча, результат](docs/images/how-it-works.svg)

Коротко: вы описываете шаги сайта один раз, программа повторяет их для
каждого аккаунта — открывает браузер через прокси, заполняет форму, берёт
код из письма и сохраняет аккаунт в файл. Капчу она не решает: замечает,
ставит паузу и зовёт вас. Разбор картинки —
[docs/how-it-works.md](docs/how-it-works.md).

## Быстрый старт

Одним файлом: скачайте [`scripts/install.bat`](scripts/install.bat), положите
в любую папку и запустите. Он склонирует проект (или обновит уже
склонированный), создаст `.venv`, поставит зависимости, докачает браузеры и
прогонит тесты. Быстрее — `install.bat --skip-tests`. Дальше этот же файл
служит обновлением: `scripts\sync.bat` внутри проекта делает то же самое.

Вручную, если удобнее по шагам:

```powershell
git clone https://github.com/KravchenkoArtyom/universal-autoregister.git
cd universal-autoregister
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m playwright install chromium
```

Затем `scripts\webui.bat`. Панель напечатает ссылку с одноразовым токеном
(`http://127.0.0.1:8765/?t=…`) и сама откроет её в браузере: без этой ссылки
панель не отвечает, поэтому чужая страница до неё не доберётся. Токен можно
задать своим (`set WEBUI_TOKEN=…`) или выключить на время отладки
(`scripts\webui.bat --no-token`).

Нужен Python 3.11+ и AdsPower либо системный Chrome (`playwright install
chrome` ставит его сам). Обновиться из GitHub — `scripts\sync.bat`: он
подтягивает изменения и доставляет новые зависимости.

## Что умеет панель

- **Обзор** — схема работы и чеклист «с чего начать»: что уже готово, а что
  стоит настроить.
- **Запуск** — очередь аккаунтов по сценарию, выбор почты, прокси и браузера,
  сколько аккаунтов делать одновременно (1–4), живой лог без опроса сервера,
  остановка после текущего аккаунта; здесь же задержки, режим капчи и
  уведомления. Полный лог и итог каждого запуска остаются в `logs/runs/`.
- **Сценарий** — создание, дублирование и удаление сценариев; шаги по секциям,
  форма шага со «своими» полями для каждого действия, перенос шага между
  секциями, проверка перед сохранением и «сухой прогон»: панель открывает
  страницу сайта и говорит, какие селекторы шагов на ней не находятся.
- **Почта** — встроенные tmail и Mail.tm плюс свои сервисы: адрес страницы и
  шаги «создать ящик», «обновить письма», «открыть письмо».
- **Прокси** — список текстом или файлом (можно перетащить), проверка связи и
  правило ротации между аккаунтами; кроме `http`/`https` понимает
  `socks5://хост:порт`.
- **Инспектор** — страница сайта показывается внутри панели: наведение
  подсвечивает элемент, клик забирает селекторы, Shift+клик кладёт элемент в
  буфер, оттуда — в шаги сценария или почтового сервиса. Селектор
  проверяется на настоящей странице.
- **Аккаунты** — что уже зарегистрировано, без паролей и ключей: поиск по
  почте, сценарию и статусу, выгрузка таблицей в CSV.

Тема оформления переключается в шапке: «Авто» (по системной настройке),
«Светлая», «Тёмная»; выбор запоминается.

Почтовые действия (`mail_create`, `mail_wait_code`, `mail_wait_link`,
`mail_open_link`, `mail_refresh`) ставятся в любое место сценария, меняются и
удаляются как обычные шаги.

## Капча, задержки, прокси

Программа делает случайные паузы между шагами и аккаунтами, а найдя капчу —
останавливается, даёт звук и системное уведомление и показывает поверх панели
полосу с кнопками «Я решил», «Пропустить аккаунт», «Остановить запуск».
Режимы: ждать человека, короткая пауза, пропускать аккаунт, только запись в
лог. Прокси берутся из файла, списка в панели или одной строки и
раздаются аккаунтам по правилу ротации; мёртвые адреса выпадают из очереди.
Подробно: [задержки и капча](docs/delays-and-captcha.md),
[прокси](docs/proxies.md).

## Сервисы на NewAPI

Панели на NewAPI (и родственном one-api) устроены одинаково: форма
регистрации с логином, паролем и — иногда — кодом из письма, а после входа
личный кабинет, где выдаётся ключ `sk-…`. Поэтому такой сервис заводится
сценарием: снимите поля инспектором, при необходимости добавьте почтовые шаги,
и очередь аккаунтов пойдёт. В комплекте два примера — eirouter и wisdomsatan.

Если из кабинета нужно ещё и забрать ключ, для сервиса делается свой
регистратор в `providers/` (как `providers/eirouter.py`: он открывает раздел
ключей, нажимает «скопировать» и складывает `sk-…` в файл аккаунтов). Всё
остальное — почта, прокси, профили браузера, капча — общее.
Подробно: [сервисы на NewAPI](docs/newapi-services.md).

## Данные и секреты

В репозиторий не попадают: `*_accounts.json`, `*_keys.txt`, `proxies.txt`,
`adspower.local.json`, `webui.local.json`, `profiles/`, `universal_profiles/`,
`logs/`, `webui_elements.json`. Держите резервные копии файлов аккаунтов и
профилей.

Файл аккаунтов и список прокси создаются с правами «только владелец»: в них
лежат пароли и ключи. Если аккаунт не дошёл до конца, снимок экрана, HTML
страницы и текст ошибки остаются в `logs/failures/` — по ним видно, какой шаг
сценария пора починить. В логах пароли, токены и ключи маскируются.

## Ответственность

Инструмент не обходит CAPTCHA и другие проверки доступа: он их только
замечает и передаёт человеку. Если сайт показывает проверку, пройдите её в
видимом окне браузера — сценарий продолжится.

Массовая регистрация нарушает правила многих сайтов. Убедитесь, что у вас есть
право регистрировать аккаунты на выбранном сайте, соблюдайте его условия
использования и держите задержки человеческими: значения по умолчанию не
случайны. Ответственность за использование — на вас.
